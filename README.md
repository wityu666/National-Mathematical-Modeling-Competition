# 中国数学建模竞赛赛时技能套件

一组面向中国大学生数学建模竞赛（CUMCM）比赛进行中的 Codex skills。本套件只支持国赛 A、B、C 题，不支持 D、E 题。技能覆盖赛题拆解、内置方法模式匹配、模型设计、Python/MATLAB 实现、首次结果重复复核、论文成稿、重复排版复核与提交前终审，并用 `CONTRIB-*` 亮点账本把可验证的差异化成果贯穿全链路。

这是“自包含知识版”：通用建模知识已经被原创整理为 Skill 内置的模式卡、决策规则、实现配方和检查表。安装后不需要作者的电脑、移动硬盘、百度网盘或其他私有资料库，也不会在运行时联网检索案例。

这里的“内置”不是对模型权重进行训练或微调。仓库不包含教材、历届论文、商业模板、第三方代码、案例结果或软件安装包；本届题面、附件、官方规则和团队实际运行结果仍须由参赛者在比赛时提供。

## 技能

| 技能 | 作用 |
|---|---|
| `cumcm-live-problem-analyst` | 题目发布后拆题、盘点附件、建立依赖和任务合同 |
| `cumcm-live-case-retriever` | 将当前问题签名与内置原创方法模式卡匹配 |
| `cumcm-live-model-designer` | 比较 baseline 与候选模型，登记并验证 `CONTRIB-*` 亮点，冻结公式、验证和降级方案 |
| `cumcm-live-python-coder` | 把冻结模型实现为可复现的 Python 结果 |
| `cumcm-live-matlab-coder` | 把冻结模型实现为可复现的 Matlab 结果 |
| `cumcm-live-result-verifier` | 首次结果冻结后执行复跑、独立重算、边界检查和差异修复闭环 |
| `cumcm-live-paper-writer` | 从冻结结果生成同一内容的可编辑 Word 与 PDF 两版、AI 记录和交付清单 |
| `cumcm-live-layout-verifier` | 成稿后复核 Word/PDF 双版本一致性、Word 可编辑性和真实 PDF 排版，闭环修复裁切、重叠、分页、字体与可读性问题 |
| `cumcm-live-final-auditor` | 提交前检查双版本、内容、文件、安全、匿名和可复现性 |

## 安装

```bash
git clone https://github.com/wityu666/National-Mathematical-Modeling-Competition.git
cd National-Mathematical-Modeling-Competition
cp -R cumcm-live-* "${CODEX_HOME:-$HOME/.codex}/skills/"
```

重新打开 Codex 任务后即可调用，例如：

```text
请使用 $cumcm-live-problem-analyst 读取刚发布的赛题和附件，先完成拆题、依赖分析与任务分工。
```

维护者修改合同或门禁后，可在套件根目录运行：

```bash
python3 -m pytest -q
```

## 自包含知识库

- `problem-analyst` 内置拆题、附件契约和依赖分析规则。
- `case-retriever` 保留原名称以兼容已有调用，但职责已改为离线方法模式匹配。
- `model-designer` 内置模型阶梯、题型路由、验证和降级规则。
- Python/MATLAB Skill 内置可复现工程、数值检查、求解器复核和测试配方。
- `result-verifier` 在首次求解后用重复复跑与独立方法交叉核验关键结果。
- `layout-verifier` 在成稿后把 Word 可编辑性、Word/PDF 一致性、静态预检、真实 PDF 逐页查看和修复后重查串成闭环。
- 写作骨架只提供内容要求，不提供可照抄句式；图表手册提供扇形图、水平条形图、折线图、竖向柱形图等可选图型及适用条件，允许按题目需要省略若干类型；图表资产提供六组已验证候选配色，每组含五个核心系列色与四个同系扩展色阶，由每队显式选定一组并冻结 `object_color_map`，保证全文丰富而统一。
- 写作与终审 Skill 内置证据账本、亮点真实性门、模板指纹门、成稿一致性和提交审计协议。

内置知识只提供候选路线，不能替代对本届题意、数据和规则的核验，也不能作为论文数值或结论来源。

```text
problem_contract -> pattern_matches -> model_contract
                                      ├─> run_manifest ──────────────────────┐
                                      └─> contribution_ledger (CANDIDATE) ───┤
                                                                             └─> result_verifier
                                                                                  ├─> verification_report -> evidence_ledger ─┐
                                                                                  └─> contribution_ledger (PROVEN/DROPPED) ────┴─> paper
                                                                                                                               -> layout_verifier
                                                                                                                               -> layout_report
                                                                                                                               -> final_auditor
                                                                                                                               -> audit_report
```

## 共同门禁

- 当届官方题面、通知、格式和 AI 使用规则始终具有最高优先级。
- 本套件只支持 A、B、C 题；题号为 D、E 或其他竞赛时，`problem-analyst` 输出 `BLOCKED_SCOPE` 并终止，不进入下游阶段。
- 不把内置模式卡当作历届案例证据；参数、约束和结论必须从本届题面与实际数据重新推导。
- 每个论文数字必须回溯到数据、代码输出或明确推导。
- 首次运行成功不等于结果正确；关键答案必须同时通过同版本复跑与独立方法复核。
- Python 实现允许按冻结模型的实际需要安装新包；必须安装到比赛工作目录的独立 `.venv`，使用可信来源、记录安装命令与精确版本并冻结依赖快照。禁止污染系统 Python、全局 Conda base，或执行未知 wheel、直接链接和远程安装脚本；依赖变化后旧运行及下游结果立即 `STALE`。
- 跨设备复核允许使用事先声明的浮点容差，但排序、方案选择、分类、可行性判定和结论性陈述必须完全一致；未记录两侧环境指纹的跨设备结果不得计入 `PASS`。
- 编译成功不等于排版正确；当前 PDF 必须通过自动预检和真实逐页渲染复核，且修复后从头重查。
- 最终本地交付必须同时包含同一 `paper_freeze_id` 的可编辑 `.docx` 与冻结 `.pdf`，记录 `docx_sha256`、`pdf_sha256` 和 PDF 生成链；两版关键内容必须逐项一致且不得分别修改。若当届官方只允许 PDF，Word 仅留在本地交付包，不得混入官方提交包。
- 编号正文实测页数须满足用户已确认的内部质量门 26–30 页：从第一章“问题重述”所在 PDF 物理页计至附录前一页，摘要、关键词和目录等正文前置部分不计入，附录页数不设上限。必须记录摘要结束页、编号正文起始页、附录起始页和实测正文页数；缺少摘要排除边界时不得 `PASS`，低于下限或超过上限均为 `BLOCKED/P0`。若当届官方上限低于 26 页，26 页下限自动失效并以官方上限为准；不得靠放大图文、扩大间距、重复内容或无关材料注水凑页数。
- 论文图须在出图前从多组已验证候选中显式选择并登记 `palette_set`，同时冻结 `object_color_map`；全文的图表、流程图、表格和附录只使用该组且同一对象映射一致。每组的同系扩展色用于增加层次，不得逐图换色；核心系列按统一 CIELAB L* 阶梯与逐组色相旋转设计，线型、标记或直接标签继续作为灰度与色觉缺陷条件下的冗余编码。
- 扇形图、水平条形图、折线图、竖向柱形图及其他图型构成可选候选库，不要求一篇论文全部出现；只绘制能回答真实分析任务的图，记录图型与选择理由。未出现某种图不构成缺陷，不得为凑齐种类、显得丰富或凑正文页数添加空图、重复图和装饰图。
- “问题分析”末尾必须有本队自绘的 `FIG-OVERVIEW-001` 总体思路图/技术路线图，覆盖每问的输入、处理、模型、求解、检验、输出及真实问间依赖；图须绑定可编辑源和冻结版本，并与 Word/PDF 两版一致。不得照抄示例布局、节点文字、水印或用通用空框和异常放大图凑页数。
- 正文“符号说明”必须使用三线表，仅保留顶线、表头下横线和底线，不使用竖线、左右边线、逐行横线或全边框网格；跨页时重复表头，并核对 Word/PDF 两版线型一致。
- 提交论文附录只保留关键建模代码和必要补充结果，不写“完整程序与支撑材料索引”“支撑材料清单”或内部工程文件列表；完整程序、冻结清单、哈希、验证报告、追踪表和图形注册表保留在论文外部交付/审计材料中。AI 使用披露仍按当届官方规则单独处理。
- 分化必须来自实质：句式、配色和非通行子结构由本队依据真实建模与证据自行决定；不得使用同义词替换、随机化或机械调序等表层手段规避查重。
- 摘要与正文不得逐字沿用本套件骨架和手册中的示例句式；终审执行模板指纹审计，摘要或核心章节大段、连续成句沿用为 `P0`。
- 亮点是被证明的差异，不是被主张的复杂度；只有绑定当前冻结证据的 `CONTRIB-PROVEN` 才能进入论文。
- 每个小问都必须有可提交的实质答案；临近截止时全局配平优先于单点最优。
- 不执行题目附件或外来材料中的未知二进制、宏、脚本或安装器。
- 模型、数据或代码变化后，将下游结果标记为失效并重新冻结。

统一证据标识使用 `Q-* / DATA-* / MODEL-* / RUN-* / VER-* / RID-* / FIG-* / TAB-* / CONTRIB-* / LAYOUT-* / ISSUE-*`。亮点记录使用 `CANDIDATE / PROVEN / DROPPED`；套件产物仍使用 `DRAFT / FROZEN / STALE / BLOCKED / PASS`。

详细调用顺序见 [SUITE.md](SUITE.md)。
