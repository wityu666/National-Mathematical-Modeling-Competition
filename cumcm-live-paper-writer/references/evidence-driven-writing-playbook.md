# 证据驱动的赛时论文成稿手册

本手册是 Skill 自带的原创写作协议，不包含获奖论文句式、教材段落或商业模板正文。它规定如何把团队真实的冻结结果转化为论文，不能生成或替代实验结果。

## 1. 建立证据账本

每个关键对象使用稳定标识：

| 类型 | 标识 | 最低证据 |
|---|---|---|
| 问题 | `Q-*` | 题面位置与合同版本 |
| 数据 | `DATA-*` | 文件、字段、单位、哈希 |
| 模型 | `MODEL-*` | 合同、公式、假设、版本 |
| 运行 | `RUN-*` | 配置、环境、seed、日志 |
| 结果 | `RID-*` | 机器可读文件与定位 |
| 图 | `FIG-*` | 图源数据与生成命令 |
| 表 | `TAB-*` | 表源数据与生成命令 |
| 引文 | `CIT-*` | 来源与支撑陈述 |
| AI 记录 | `AI-*` | 工具、用途、交互、采纳 |

维护映射：

```text
论文位置 -> 证据 ID -> 文件/页码/单元格/命令 -> 冻结版本
```

没有证据 ID 的关键数字不得进入摘要、核心表或结论。

## 2. 论文总结构

具体格式服从当届官方规则。内容通常按以下逻辑组织：

1. 问题重述与交付目标；
2. 问题分析与总体路线；
3. 模型假设及影响；
4. 符号、单位和数据说明；
5. 各小问的模型、求解、结果和检验；
6. 敏感性、稳健性和边界；
7. 模型评价与可执行建议；
8. 参考文献、AI 使用说明和附录。

章节顺序可以调整，但证据链不能断。

## 3. 每小问写作单元

按固定八步：

1. **目标与接口**：准确回答题面要求，并说明与前后小问的依赖；
2. **数据**：说明范围、字段、单位和处理；
3. **方法**：解释为什么选 baseline 与主模型；
4. **模型**：变量、参数、公式、目标、约束、边界；
5. **求解**：配置、环境、seed、停止条件；
6. **结果与解释**：数字、图表、比较、机制或实际含义；
7. **验证**：代回/约束复核、独立路线、敏感性或 baseline；
8. **边界与下问接口**：稳定区间、失效条件、回退和复用产物。

每个小问结束时明确一句可回答题面的结论，并绑定 `RID-*`。

## 4. 摘要反写

摘要最后写，只使用已冻结结果。每个小问用四要素：

```text
针对什么 -> 建立/执行什么 -> 得到什么关键结果 -> 如何验证
```

摘要避免：

- 大段背景或空泛意义；
- 只罗列算法名；
- 正文没有出现的数字；
- “效果很好”“结果准确”等无指标评价；
- 把相关关系写成因果；
- 把可行解写成全局最优。

## 5. 数学表达

- 符号首次出现即定义，给单位和取值域。
- 同一符号不复用；向量、矩阵、集合和标量样式一致。
- 目标函数与所有关键约束完整呈现。
- 题面硬约束与团队假设分开说明。
- 公式后的参数能回到数据字段或估计步骤。
- 代码变量与论文符号通过映射表对应。
- 有容差、边界或初值时明确写出。

## 6. 结果叙事

每个核心结果使用：

```text
结论 -> 图表/数值证据 -> 比较 -> 解释 -> 适用范围
```

示例结构：

> 在已定义情景和约束下，方案 A 的目标值为 `RID-Q2-004`，相对 baseline 的变化见 `TAB-Q2-002`。逐约束复核未超过合同容差；当参数超过敏感性区间时，该排序可能改变。

实际成稿用团队真实数字替换标识。不要把示例句当结果。

## 7. 图表协议

每张图或表必须：

- 只承担一个主要结论；
- 标明对象、时间范围、单位、图例和不确定性；
- 在正文先引用再解释；
- 有可读字号和灰度可辨识编码；
- 与机器可读源数据和生成代码关联；
- 编号连续且题注自足；
- 不手工改数或仅保留截图。

坐标轴截断、双轴、对数尺度、平滑或归一化会改变理解时，必须明确说明。

## 8. 误差、稳健性与局限

只写真实执行过的检查：

- 预测：样本外误差、残差、区间覆盖；
- 分类：类别指标、阈值、误判；
- 评价：权重、标准化与排名敏感性；
- 优化：目标和约束独立复核、最优性边界；
- 仿真：多 seed、置信区间、收敛；
- 机理：量纲、守恒、参数可识别和边界。

局限应对应机制，例如“外生变量在预测期不可获得”或“参数只在给定区间可识别”，而非空泛写“数据较少”。

## 9. 引文协议

引文表至少记录作者/机构、标题、出处、访问日期、论文位置和支撑陈述。原则：

- 引文紧邻它支撑的事实或方法来源；
- 不用二手转述替代可取得的一手来源；
- 动态数据记录访问时间和版本；
- 算法常识不代替本届数据证据；
- 不虚构 DOI、作者、页码或结论。

## 10. AI 使用记录

以当届官方规则为准。每条真实记录包含：

- 工具与使用时显示的版本；
- 时间与时区；
- 用途和阶段；
- 足以审计的关键输入与输出；
- 采用、弃用和人工修改；
- 影响的论文、代码、图表或分析位置；
- 人工验证方式。

模板中的示例工具、提示词和采纳说明不能当作真实记录。

## 11. Word 与 LaTeX 路线

### Word

- 使用样式、题注、交叉引用和公式对象；
- 清除修订、批注、占位符、隐藏文字和个人元数据；
- 不启用宏，不让手工编号替代自动字段；
- 从冻结主稿导出 PDF。

### LaTeX

- 使用最小主文件、唯一标签、自动引用和可复现编译命令；
- 检查缺图、缺包、未定义引用、重复标签、字体和 overfull box；
- 图片名和路径稳定，保存编译日志；
- 从冻结源文件生成 PDF。

只设一份内容母版和一条主路线。另一格式若保留，必须从同一冻结内容生成并做差异核对。

## 12. 成稿一致性门

交给终审前确认：

- 题号和小问顺序正确；
- 摘要、正文、图表和结论的模型名与数字一致；
- 符号、单位、时间范围、样本量和有效数字一致；
- 所有图、表、公式、章节和引文被引用；
- 结果均来自 `FROZEN` 运行；
- 占位符、模板提示、示例数据、批注和修订已清除；
- PDF 已真实渲染并逐页检查；
- 当届规则与 AI 记录已有可审计证据。

发现冲突时回到证据源修正，不凭“更合理”手工改写冻结数字。
