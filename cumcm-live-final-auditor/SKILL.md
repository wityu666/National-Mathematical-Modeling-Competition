# CUMCM 提交前终稿审计

## 审计原则

- 把当届官方规则作为唯一合规基线；同时执行用户已确认的内部质量门“编号正文默认 26–30 页、摘要不计、附录不限页”。26 页下限不是官方要求；若当届官方上限低于 26 页，该下限自动失效并以官方上限为准。
- 对冻结后的本地交付包与官方提交候选目录执行只读审计，不在审计过程中偷偷修改论文或代码。
- 同时检查内容、文件、安全、可复现性和真实渲染效果。
- 任何关键证据缺失都应标记为阻塞，而不是推断通过。
- 不执行外来 `.exe`、`.lnk`、未知二进制或 Office 宏；不引用其他竞赛规则判断国赛。

开始前按需读取：

- 自包含提交审计协议：[references/submission-audit-protocol.md](references/submission-audit-protocol.md)
- 报告格式：[assets/audit-report-template.md](assets/audit-report-template.md)

## 1. 固定审计输入

记录：

1. 提交候选目录的绝对路径。
2. 冻结时间和版本标识。
3. 当届官方规则文件、链接或用户提供的规则快照。
4. 主排版路线：Word 或 LaTeX。
5. 用户或官方给出的文件大小阈值；没有依据时不自创阈值。
6. 预期题号、论文文件名、附件结构和 AI 披露方式。
7. 当前 `contribution-ledger.md`、版本、状态及其绑定的模型冻结标识。
8. 当前 `verification-report.md`、`VER-*`、状态及其绑定的 `model_freeze_id/run_id`。
9. 当前 `layout-report.md`、`LAYOUT-*`、状态、论文源版本及其绑定的 `paper_freeze_id`、`docx_sha256` 与 `pdf_sha256`。
10. 摘要起止物理页、`main_start_pdf_page`（第一章起始页）、`appendix_start_pdf_page`、`total_pdf_pages`、`main_body_pages` 及页数边界证据。
11. `paper_freeze_id`、Word 路径与 `docx_sha256`、PDF 路径与 `pdf_sha256`、`pdf_generation_source`，以及 Word/PDF 双版本一致性报告。
12. 本地交付包和官方提交候选目录的独立清单；当届规则未允许 Word 时，确认 `.docx` 只在本地交付包中。

审计期间如候选文件变化，原审计结果立即失效；重新冻结后再审。

## 2. 运行静态目录审计

本节命令只扫描按当届规则整理的“官方提交候选目录”。Word 若不在当届允许提交的格式中，只在本地交付包做双版本审计，不得为了满足本套件的两版交付而混入官方提交候选目录。

执行：

```bash
python3 scripts/audit_submission.py /absolute/path/to/submission
```

需要机器可读输出时：

```bash
python3 scripts/audit_submission.py /absolute/path/to/submission --json
```

仅当当届官方规则明确给出 PDF 大小限制时传入：

```bash
python3 scripts/audit_submission.py /absolute/path/to/submission --max-pdf-mb 20
```

脚本只使用 Python 标准库并执行只读扫描。它会：

- 列出相对路径、字节数和 SHA-256。
- 验证至少存在一个带 PDF 文件头的 `.pdf`。
- 验证至少存在一个模型源代码文件。
- 标记 `.exe`、`.lnk`、宏文档、符号链接、`crack`、`keygen`、`破解`、`注册机` 等风险项。
- 在用户提供阈值时标记超限 PDF。

退出码：

- `0`：脚本层面的硬检查通过。
- `1`：缺 PDF、缺源代码、发现危险项、超限或扫描错误。
- `2`：命令参数或目标路径错误。

脚本通过不代表论文内容或官方规则已经通过。

修改审计脚本后，在 Skill 根目录运行回归测试：

```bash
python3 -m pytest -q tests
```

测试 fixture 仅包含不可执行的占位字节和假文件名；不得运行其中的 `.exe`。

## 3. 核对当届官方规则

逐条建立“官方要求—证据—状态”矩阵，至少覆盖：

- 题号、文件名、提交格式和附件结构。
- 首页、摘要、目录、页码、页数或文件大小要求。
- 编号正文默认 26–30 页、摘要不计、附录不限页；摘要/编号正文/附录边界以最终 PDF 物理页核验。26 页下限属于用户已确认的内部质量门，当届官方上限低于 26 页时自动失效。
- 匿名、承诺书、编号页、指导教师或学校信息规则。
- 代码、数据、支撑材料和压缩包规则。
- AI 使用、声明、标注和交互记录规则。
- 截止时间、提交成功确认和允许重传条件。

官方规则未取得时，将所有依赖当届规定的项目标记为“未核验”，不得给出合规通过结论。

## 4. 审计论文内容

检查以下一致性：

- 题号与每小问顺序正确。
- “问题分析”末尾存在 `FIG-OVERVIEW-001` 总体思路图/技术路线图；每个实际小问均能追踪到输入/数据或上问产物、关键处理/假设、模型或数学构造、算法/求解器、真实检验和输出/答案，且共享模块、传递变量/文件与依赖方向和当前冻结合同、正文一致。缺图或漏掉任一小问按 `P1` 处理；图中出现正文未采用的方法、未执行验证、虚构依赖或与核心模型矛盾，按 `P0` 处理。
- 摘要中的模型、数据范围、关键数值和结论与正文一致。
- 关键词紧随摘要，目录位于关键词之后、正文之前；目录由排版工具自动生成，标题文字、层级和页码与最终正文一致，目录标题未收录自身，也不存在手工维护的旧页码。
- 符号定义、单位、时间范围、样本量和有效数字一致。
- “符号说明”以独立三线表放在正文模型假设之后、数据/建模章节之前，没有把完整符号表只放在附录；表中含义、单位、取值范围与公式附近定义一致。三线表只保留顶线、表头下横线和底线，不得出现竖线、左右边线、逐行横线或全边框网格；未采用三线表按 `P1` 处理，修复前不得 `PASS`。
- 公式中的变量均有定义，约束和目标与代码实现一致。
- 图、表、公式、章节和参考文献编号连续且均被正文引用。
- 第三章只列全局假设，各问专有假设在对应章节就近说明且能从第三章索引；不存在混入全局章节或未说明的隐含假设。
- 公式按所在章采用“章号-序号”格式并由排版工具自动编号、自动交叉引用，例如第六章从式(6-1)起；每章内连续、无跳号、无重号，删除或移动公式后的引用仍正确。正文不得使用“上式”“下式”代替明确编号。
- 图表数值可回溯到冻结输出，不存在手工改数。
- 逐图核对实际图型与分析任务是否匹配：扇形图只用于少量类别的部分—整体构成，水平条形图用于排序/长标签，折线图只连接真实有序横轴，竖向柱形图原则上使用零基线。扇形图、水平条形图、折线图、竖向柱形图及其他候选类型允许有几种或全部不出现；未出现本身不得判为 `P0/P1`。
- 若为了凑齐图型或正文页数加入空图、重复图、装饰图，按反注水 `P0` 处理；实际图型不适配任务、轴或标签误导但未改变核心结论时按 `P1`，导致结论失真时按 `P0`。
- 误差、敏感性、稳健性或模型检验陈述与实际结果一致。
- 逐问核对七项内容门——目标、难点与接口，数据与处理，模型或数学构造，求解与复现，结果与解释，真实检验，直接答案/最终交付——是否均在正文中有明确位置。任一问缺项按 `P1` 处理；若缺失“模型或数学构造”“求解与复现”“真实检验”或“直接答案/最终交付”中的任意一项，按 `P0` 处理，因为该问实质未作答。
- 逐问核对主体章节是否设置能概括实际论证内容的描述性小标题。任一问整章没有小标题、以无层次长段呈现，或标题与其下内容明显不符，按 `P1` 处理；若把七项内容门逐字复制为三问统一标题结构，同时进入模板指纹审计。
- 核对附录是否收录实际生成最终模型、求解结果或关键验证的建模代码。每条代码须有 `CODE-*`、相对源文件与函数/脚本段、冻结版本及对应 `MODEL/RUN/RID/FIG/TAB`，并与提交包中的完整源代码一致。附录完全缺少关键建模代码、代码与冻结版本不一致或无法映射核心结果，按 `P0` 处理；仅缺少非核心辅助片段按 `P1` 处理。
- 若附录主要建模代码缺失、未定位到最终 PDF 物理页或只以占位符/截图/非核心辅助代码冒充，状态必须为 `BLOCKED_APPENDIX_CODE`；不得因提交包另有完整源代码而豁免论文附录代码门。
- 核对提交论文没有“完整程序与支撑材料索引”“支撑材料清单”或类似章节，且未将完整程序文件名、内部目录、冻结清单/哈希、`verification_report`、事实追踪表、图形注册表或 AI 交互文件索引写入 Word/PDF。此类清单应只存在于论文外部的运行清单、交付清单和审计报告；论文中出现时按 `P1` 处理并删除，若同时暴露本机绝对路径、身份、密钥或其他敏感信息则按 `P0` 处理。关键建模代码附录和官方要求的 AI 披露不因此删除。
- 优缺点和适用边界不是无证据套话。
- 引文实际支撑相邻陈述，来源信息足以定位。
- 所有占位符、模板提示、示例数据、批注和修订已清除。

对关键数字做反向抽样：从摘要、核心表格和结论各选若干数值，追溯到源文件、代码输出或运行记录。任一关键数字无法追溯即为阻塞。

同时核对每个关键结果都出现在同版本 `VER-* PASS` 报告中，Round A 同环境复跑、Round B 独立方法复核和题型硬门均为通过。报告缺失、`STALE/BLOCKED`、只完成同代码复跑而没有独立复核，或版本不一致，均为 `P0`。

同时核对当前 `LAYOUT-*` 报告为 `PASS/FROZEN`，绑定同一 `paper_freeze_id` 下的 `docx_sha256` 与 `pdf_sha256`，且包含自动预检、Word 可编辑性、双版本一致性和真实 PDF 逐页视觉复核证据。报告缺失、`STALE/BLOCKED`、只做静态预检、未查看真实页面、未检查 Word 或任一哈希不一致，均为 `P0`。

先核对 `main_start_pdf_page` 确为第一章“问题重述”所在物理页，摘要、关键词和目录等正文前置部分未计入；再独立重算 `main_body_pages = appendix_start_pdf_page - main_start_pdf_page`，没有附录时编号正文计算到 PDF 最后一页。默认要求 `26 <= main_body_pages <= 30`：编号正文低于 26 页意味着深度可能不足或小问未实质作答，超过 30 页仍按原规则阻断，二者均为 `P0`。若当届官方上限低于 26 页，26 页下限自动失效并以该官方上限为准；附录页数本身不设上限。

页数边界任何一项缺失或无法证明摘要已排除时，输出 `BLOCKED_PAGE_BOUNDARY`；实测正文落在有效区间之外时输出 `BLOCKED_PAGE_RANGE`。两者均为 `P0`，不得把 `UNVERIFIED`、脚本未报其他问题或人工目测“差不多”解释为通过。

执行反注水审计，命中任一项均为 `P0`：

- 放大图片尺寸、增大字号行距、加宽页边距等版式注水；
- 把完整代码、批量中间表、原始数据清单搬进正文充页数；
- 复述题面、重复叙述同一结论或让同一图表反复出现；
- 添加与结论无关的装饰性图表；
- 用通用空框总体思路图、重复正文的装饰流程图或异常放大的 `FIG-OVERVIEW-001` 凑页数；
- 大段罗列未被正文使用的候选算法或公式推导。

发现编号正文不足 26 页时，正确修复是回到逐问七项内容门，补足实质模型、求解、验证、结果解释和边界分析；不得通过扩大排版修复。把核心模型、结果、验证、符号表或复现入口挪入附录规避 30 页上限，同样为 `P0`。

## 5. 模板指纹审计

由人工或 Agent 对真实成稿逐项核对，不给静态目录扫描脚本增加文档解析能力：

- 检查成稿是否逐字沿用了本套件骨架与手册中的示例句式、示例性的固定子结构顺序或配色说明文字。
- 核对总体思路图是否照抄参考论文、示例图片或本套件说明中的节点文字、固定布局、色块顺序和连接方式；水印、广告、机构标识或截图界面不得进入成稿。通用的方框与箭头本身不计为指纹，只有可识别的成套布局或文字表达沿用才按本节分级。
- 重点检查摘要、问题分析、结果解释和模型评价四处，并按 `references/submission-audit-protocol.md` 的指纹短语清单逐条比对。
- 单句或短片段逐字沿用示例句式，记为 `P1`。
- 摘要或任一核心章节出现大段、连续成句的沿用，记为 `P0`；此类指纹可能触发查重并被判定违规。
- 修复时由本队根据实际模型、证据和论证关系重新组织表达，不得用同义词替换、机械调序或其他表层改写敷衍；修复后重新冻结并复审。
- “问题重述、问题分析、模型假设、符号说明、模型的建立与求解、模型检验、模型评价与推广、参考文献、附录”等国赛通行章节名不计为指纹，不得因此要求改名。

未查看真实成稿或未完成短语清单核对时，`template_fingerprint_checked=UNVERIFIED`，最终状态不得为 `PASS`。

## 6. 审计亮点真实性

对摘要、引言、正文洞察、模型评价和推广中的每条差异化主张反向抽查：

1. 文中存在稳定 `CONTRIB-*`，且能定位到当前账本；
2. 账本状态为 `FROZEN`，记录状态为 `PROVEN`，绑定当前 `model_freeze_id`；
3. `claim` 可证伪，`baseline_expectation` 与实际对照口径一致；
4. `evidence_ids` 能定位到专门、冻结、可复现的 `RID/FIG/TAB/MODEL`；
5. `proof` 的量化差异确实由运行结果产生，未挑选最好 seed、折或情景；
6. `cost_risk`、失效边界、`placement` 和 `fallback` 已披露且与正文一致。

无证据亮点、把 `CANDIDATE/DROPPED` 写成已证明贡献、账本与正文 `proof` 不一致、或模型版本已失效，均为 `P0` 阻塞，等级同关键数字无法追溯。修复动作是删除/降级主张或重新运行并冻结证据，不得只改措辞。

## 7. 审计 AI 使用记录

核对：

- 工具名称、版本、时间和用途完整。
- 关键输入、输出、采纳内容和人工修改相互匹配。
- 每条采纳内容能定位到论文、代码、图表或分析环节。
- 正文标注、参考文献或独立说明符合当届官方规则。
- 没有把模板示例、其他团队记录或虚构交互当成真实记录。
- AI 生成的数字、引文和事实均经过独立验证。

发现工具清单与交互记录错配、采纳说明写错工具名或缺少论文位置时，标记为阻塞。

## 8. 审计 Word/PDF 两版与排版源文件

先审计本地交付包中的两版成稿：

- 必须同时存在真实 `.docx` 和 `.pdf`，共享同一 `paper_freeze_id`，并记录 `docx_sha256`、`pdf_sha256` 与 `pdf_generation_source`；
- 在禁用宏的环境中打开 Word，确认无修复提示，正文、表格、公式与附录代码可选择和编辑，不是整页截图、宏文档或改扩展名文件；
- 逐项比较题目、摘要、关键词、目录层级、章标题与小标题、关键数值与结论、`RID/FIG/TAB/CODE/CONTRIB`、图表/公式/参考文献编号和附录关键代码；分页差异可记录，内容差异不允许；
- 任一版本发生变化时，原双哈希、`LAYOUT-* PASS` 与终审状态全部变为 `STALE`，必须从唯一主稿同步再生两版并复审；
- 根据当届官方规则单独核对官方提交候选目录。若只允许 PDF，Word 必须留在本地交付包，不得上传或压入官方提交包。

### Word 主路线

- 确认提交 PDF 来自冻结 Word 主稿。
- 检查标题样式、题注、交叉引用、公式对象、分页和目录字段。
- 确认无修订、批注、模板提示语、宏依赖和不应出现的个人信息。
- 不通过打开旧宏或执行嵌入对象来“验证”文件。

### LaTeX 主路线

- 保存最终编译命令和日志。
- 检查缺包、缺图、未定义引用、重复标签、字体替换和 overfull box。
- 确认提交 PDF 与冻结 `.tex`、类文件、图片及参考文献一致。
- 不把本地带推广内容或缺图的示例文件直接视为可提交模板。

如同时存在 Word 和 LaTeX 源，确认哪一个是唯一主稿。LaTeX 主路线下，PDF 来自冻结 LaTeX，Word 是同一冻结内容的可编辑伴随版；不得要求像素级分页相同，但上述内容与证据必须一致。

## 9. 执行 PDF 视觉 QA

必须渲染真实 PDF 并逐页查看。文本抽取、页数统计或编译成功不能替代视觉检查。

先抽查上游 `LAYOUT-* PASS` 的页码、截图和问题闭环，再独立查看当前提交 PDF；不得直接继承排版复核结论。

检查：

- 首页、摘要、关键词、目录、各章起始页、参考文献、附录及最后一页。
- 摘要结束页、编号正文第一章起始页、正文最后一页、附录起始页及其前后页；独立确认摘要未计入、编号正文处于有效区间（默认 26–30 页）、附录页数不限，并检查是否存在为达到下限而实施的版式或内容注水。
- 文字、公式、图表无裁切、重叠、乱码或异常空白。
- 图表清晰，坐标、单位、图例和题注完整。
- 总体思路图位于问题分析末尾，题号分组、节点、箭头、共享模块和问间依赖在最终尺寸下清晰；图号、可编辑源、生成入口与冻结版本可定位，Word/PDF 两版内容一致，且没有裁切、跨页断裂、低清文字、水印或截图界面。
- 论文图使用运行清单中显式登记的同一个 `palette_set`，同一对象跨图颜色一致；任何配色例外都有科学可读性理由和 QA 证据。
- 已使用的扇形图、水平条形图、折线图、竖向柱形图及其他图型均有分析任务和选择理由；未使用的候选图型记为 `NOT_APPLICABLE`，不因缺少图型判错，也不存在为凑齐种类生成的装饰图。
- 正文符号表为三线表且清晰可读，仅有顶线、表头下横线和底线，无竖线、左右边线或逐行横线；Word/PDF 两版线型一致，跨页表头、上下标、单位和列宽没有因导出而错位。
- 问题一、问题二、问题三均有清晰可见的小标题，标题层级、编号、间距、分页和对应正文一致；不存在整章无层次长段或孤立页末标题。
- 三线表、跨页表和长公式排版可读；附录关键建模代码为可复制的等宽文本而非截图，字号、缩进、换行、跨页和页边界清楚。
- 附录没有完整程序与支撑材料索引、支撑材料清单或内部工程文件列表；必要的关键代码仍可读，内部目录清单和哈希只在论文外部审计材料中出现。
- 页码、页眉页脚和匿名信息符合当届规则。
- 彩色图转灰度后仍可辨认；PDF 缩放后细线和小字仍清晰。

发现视觉问题时，把页码、对象和截图证据写入报告，不只写“排版有问题”。

## 10. 审计可复现性与提交包

在安全、隔离环境中检查：

- 源代码入口、依赖、版本、随机种子和运行命令已说明。
- 附录 `CODE-*` 与冻结源文件中的对应函数/脚本段逐项一致，并能映射到正文使用的 `MODEL/RUN/RID/FIG/TAB`；完整工程路径与 SHA-256 可定位。
- `verification-report.md` 与最终运行、证据账本、亮点账本和论文使用同一冻结版本。
- 论文外部的支撑材料清单与实际文件一一对应，且该清单没有被复制为论文附录章节。
- 代码使用相对路径，未引用队员本机绝对路径或密钥。
- 正文结果与冻结输出一致。
- 提交包不含缓存、临时文件、旧版本、商业资料、无关大文件或危险程序。
- 最终目录清单和 SHA-256 已写入报告。
- 本地交付包含 Word/PDF 两版及双哈希；官方提交包只含当届规则允许的文件，两份清单不得混淆。

不要为了测试可复现性执行未知二进制、快捷方式、破解工具或宏。

## 11. 输出结论

使用 `assets/audit-report-template.md` 输出：

- `PASS`：当届官方规则、内容、文件、安全、可复现性、绑定同一 `paper_freeze_id` 与双哈希的 `LAYOUT-* PASS`、Word/PDF 一致性和独立视觉 QA 全部通过。
- `BLOCKED`：存在任一硬阻塞或规则未取得。

严重级别：

- `P0`：会导致无法提交、违规、缺少 Word/PDF 任一交付版、Word 不可编辑、双版本冻结标识/哈希/关键内容不一致、Word 误入官方不允许的提交包、编号正文低于有效下限或超过有效上限、为凑足 26 页实施版式/内容注水、把摘要计入正文、摘要/正文/附录边界造假或未核验、错误结论、泄露身份、危险文件进入提交包，或缺少同版本 `VER-* PASS`、同版本 `LAYOUT-* PASS`、亮点/关键数字无法由冻结证据支持，或摘要/核心章节大段沿用模板指纹。
- 状态码映射：页数边界缺失为 `BLOCKED_PAGE_BOUNDARY`，正文越界为 `BLOCKED_PAGE_RANGE`，附录主要建模代码缺失或未核验为 `BLOCKED_APPENDIX_CODE`；三者都不得降级为 `P1/P2`。
- `P1`：明显影响评阅、复现或可信度。
- `P2`：不阻塞提交但建议修复的表达或版式问题。

每个问题必须给出证据、位置、影响和最小修复动作。修复后重新冻结并完整复审，不沿用旧的 PASS。
