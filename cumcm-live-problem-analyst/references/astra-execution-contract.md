# GPT-6 Astra 赛时执行约定

本约定适用于套件的九个角色，目标模型为 GPT-6 Astra（`gpt-6-astra`）。它补充赛时执行、恢复和分工方式，不替代各技能的输入合同、冻结规则与完成条件。首次进入本套件或恢复任务时读取；同一任务内未变更的约定不必反复加载。

## 1. 模型与工具边界

- 在 Codex 的模型选择器中选择 GPT-6 Astra；技能文字和 `agents/openai.yaml` 不会切换实际模型，也不得添加无效的 `model`、`reasoning_effort` 等配置字段。
- 推理强度使用宿主当前支持且已选定的设置，不一律提升到最高档。AI 使用记录登记实际可见的模型与设置；不可见的值写 `unknown`，不得根据本文件倒填成 Astra。仅模型切换不使未变动的冻结数学结果失效；若修改了模型、代码、依赖或证据，仍按既有规则标记下游 `STALE`。
- 先定位本技能目录与比赛工作目录。文中的 `scripts/...` 命令以对应技能目录为基准，输入输出指向比赛工作目录；不得假定下载者使用作者的路径。
- 按当前阶段探测真实可用能力：Python/数值库、MATLAB/许可证与工具箱、Word 编辑与导出、PDF 渲染与页面查看、子代理或后台任务工具。模型名称不等于这些能力已存在。缺失时走本角色的补齐或降级流程；没有实际运行、导出或查看，就不能把该检查记为通过。

## 2. 入口、范围与继续执行

- 全新比赛任务从 `cumcm-live-problem-analyst` 开始。按阶段直接调用下游角色时，也先核验当前 `problem_contract` 的赛事、A/B/C 题号和状态；D、E 或其他竞赛立即输出 `BLOCKED_SCOPE`，不开始建模或写作。题号不明先查题面/合同，仍无法确定才询问；不凭相似题型猜题号。
- 已有任务从首个未满足门禁的阶段恢复，不因换模型、换任务上下文而从头拆题。使用下游技能不等于允许绕过缺失、未冻结或已失效的上游产物。
- 用户要求完成整题/完整交付时，在已有授权内推进通过门禁后的下一阶段；没有新决策或阻断，不为例行命名、执行命令、文件导出反复请求确认。用户只要求某一阶段、诊断或审查时止于该范围；用户指定的暂停决策点仍须遵守。外部发布、正式提交和对外发送不因“完成”而自动获准。
- 赛中补充要求合并到当前目标；状态询问或侧问不取消原任务，明确替换任务时才切换目标。会改变模型路线、数据口径或结论的缺失信息不能当作格式选择自行决定。
- 出现阻断时，报告实际状态码、触发它的技能条款、缺少的证据及最小下一步，不只说“技能不允许”。规则或范围阻断时停止相关解题；其他阻断仅允许继续不消费被阻断产物、且在用户授权内的独立工作。不得把局部完成写成全链路 PASS。

## 3. 长任务与断点恢复

在既有工作日志或交接记录中维护以下恢复信息；没有工作日志时可在比赛工作目录建立 `handoff.md`。这是内部工作记录，不进入提交论文，也不新增证据 ID 或替代正式合同。

| 信息 | 记录要求 |
|---|---|
| 任务范围与授权 | 当前目标、最新用户约束、已确认选项、允许继续到哪一步、必须暂停的位置 |
| 阶段与版本 | 当前角色、合同版本、`freeze_id/run_id/paper_freeze_id`、适用状态 |
| 证据入口 | 原始输入与冻结产物路径、已有哈希、当前 `VER/LAYOUT` 报告及其绑定版本 |
| 已完成与未完成 | 已实际执行的检查、未关闭 ISSUE、阻断项、下一步动作；不记录推测为完成 |
| 运行中的工作 | 命令或代理任务、任务/会话标识、负责人、独立输出目录、预期产物与停止条件 |
| AI 使用信息 | `assistant_model`、可见推理设置、参与阶段；不可见字段写 `unknown` |

恢复时重读当前合同、日志和相关报告，核对文件是否仍存在、状态/版本与已登记哈希是否匹配。聊天摘要、代理口头“已完成”或旧截图只作定位线索，不作为冻结依据。失效链按各角色既有规则处理；不覆盖旧运行，不因上下文丢失重复启动仍在运行的任务。

## 4. 并行分工与结果收回

- 有可用子代理工具且能提高效率时，将冻结输入下互不依赖的小问实现、候选模型核查或不同页组检查并行分派；依赖尚未产出的结果的任务不得提前启动。生产完成并冻结后，才启动消费该版本的复核。
- 每项分工指定输入版本、输出范围、文件/目录所有权、预算、完成证据和停止条件。告知协作者不要覆盖他人改动；共享合同和最终论文由一个负责人合并，避免多人同时修改同一文件。
- 主代理负责收回产物、检查退出状态/日志、合并一致版本并执行本阶段交接门。子代理启动成功、进度消息、文件刚生成或后台进程仍运行都不是完成；使用宿主提供的等待/查询机制获取真实结果，随后才能冻结。
- 子代理或异步工具不可用时，改为串行完成，不把工具缺失当作免检理由。不在 YAML 中发明调度字段，也不把某个宿主的工具名写成下载者必须具备的唯一实现。

## 5. Astra 的推理用于设计，证据用于定论

- 模型设计可比较候选路线和可证伪假设；数值、图形趋势及 `CONTRIB-PROVEN` 必须来自完成的实际运行和同版本验证，不从模型自信或示例补写。
- 换一个代理或换一个模型不等于独立验证。复核者从题面与冻结合同建立预期，用本角色要求的独立方法和可执行检查取证；不得把生产者的结论直接复制为验证结果。无子代理时也须保留独立检查器/第二方法，Round A、Round B 与跨设备容差政策不变。
- 对同一冻结版本，已满足的检查可以凭当前有效证据承接；不得无故增加重复修复轮次或一遍遍重跑未变化的检查。任何会使证据过期的改动仍触发既有重检，尤其不能让重导出的 PDF 继承旧视觉 PASS。
- 阶段汇报简要说明完成产物、验证状态、未解决问题与下一步。论文仍按本队数学逻辑组织正文、小标题和内容门，不把内部执行清单改写为论文，也不因为模型偏好而套用统一句式。

依据 2026-09-05 核对的 [OpenAI GPT-6 Astra 使用与迁移指南](https://developers.openai.com/api/docs/guides/latest-model/gpt-6-astra.md)，针对指令边界、赛中续做、代理分工和可观察的完成证据作定点适配。本约定不是微调、模型自动切换或完整国赛效果评测的声明；实际可用模型与工具以当前 Codex 宿主为准。
